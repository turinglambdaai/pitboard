# 汽车行业词表（Vocabulary）

pitboard 用三张词表表达汽车行业的技术趋势。本文档记录词表内容、
**为什么是这些词**（判据）、以及维护规则。热词体系必须有编辑判断：
不从用户反馈被动加词，也不凭感觉加词——每个词都要过下面的判据。

## 三张词表

| 词表 | 位置 | 作用 |
| --- | --- | --- |
| 话题雷达词表 | `config/sources.json` 的 `watch_topics`（内置默认 `sources.rkt`） | 跨期话题页 `/topics/`，表达「行业在聊什么方向」 |
| 热度词表 | `pitboard/score.rkt` 的 `hot-terms` | 聚簇热度加成，表达「什么内容对读者更有价值」 |
| GitHub 相关性门控 | `sources.rkt` 的 `gh-relevance-regex` | 拦截非汽车仓库混入开源雷达 |

话题条目支持**别名**：`{"term": "线控底盘", "aka": ["by-wire", "线控制动"]}`。
中文主词配英文媒体别名，否则英文信源永远进不了中文话题。
匹配规则见「匹配语义」一节。

## 判据（一个词进入词表的四个门槛）

1. **标准与技术栈结构**——词在 E/E 体系里有明确位置（如 AUTOSAR/DDS/UDS
   属于基础软件与诊断栈，线控底盘属于执行层架构演进）。
2. **行业趋势曲线**——是未来 2–3 年的确定性方向（线控底盘、端到端、
   固态电池、数据闭环），不是一时的营销词。
3. **画像契合**——读者是汽车 E/E 工程师（见 docs/SOURCES.md 读者画像）。
   纯整车消费向词（如具体车型名）不进方向组。
4. **自有语料频次实测**——上线前用归档语料跑频次（2026-10-14 实测：
   端到端 7 条/周、智能座舱 2、OTA 1；线控底盘/固态电池 0——0 不否决，
   因为我们的信源对这些领域覆盖弱，话题雷达本就是跨期积累设计，
   见「0 体量词的处理」）。

不设体量门槛进话题页，但体量数据决定**热度权重**与**别名取舍**。

## 匹配语义（为什么不是子串）

- ASCII/缩写词按**词邻界**匹配：`adds` 不得命中 DDS，`rotary` 不得命中
  OTA；允许英文复数（robotaxis 归 Robotaxi）。
- 邻界而不用 `\b`：汉字在 Unicode 正则里算词字符，`\b` 会漏掉
  「UDS诊断」「DDS中间件」这类字母紧贴汉字的写法。
- CJK 词保持子串匹配（中文无词边界）。
- 话题词支持别名，主词决定页面 slug，别名只参与匹配。

## 维护规则

1. **季度复核**一次全表：删死词、降权过气词、提权爆发词。
2. 新词进表前先跑语料频次（probe 脚本：对归档 digest 逐词计数）。
3. 用户/读者建议的词同样过四门槛，通过才进，并在本文档记录判据。
4. 热度词权重遵循两级：工程/趋势核心 0.5–1.2，通用词 0.2–0.4。
5. 词表变更必须带测试（匹配语义回归）并在 CHANGELOG 记录。
